# wechat-formatter · 公众号 Markdown 排版工具

把 Markdown 文章一键转换成**可直接复制到公众号后台**的精美排版 HTML。所有样式内联，粘贴后格式完整保留；并提供一个可反复使用的**在线编辑器**，支持实时预览、配色 × 结构格式自由组合、草稿自动保存。

---

## 项目介绍

写公众号最痛的一点是排版：后台只认**写在每个标签上的内联样式**（`style="..."`），不认 `<style>`、`<class>`、外部 CSS。手写内联样式既繁琐又难看。本工具用一份 Markdown 源文，自动产出「复制到公众号即所见」的排版结果。

**核心特性**

- 📋 **复制即得**：所有样式内联，富文本写入剪贴板，到后台 `Ctrl/⌘+V` 粘贴即保留格式。
- 🎨 **配色 × 结构格式解耦**：10 套配色 × 10 套结构格式 = **100 种组合**，预览页顶部两组选择器实时切换，正文即时更新。
- ✍️ **编辑 + 预览**：预览页默认「左编辑 / 右预览」，改稿实时刷新；分隔条可拖拽调宽窄，「📱 手机」看窄屏效果。
- 🧱 **扩展块语法**：分栏线、标签卡片、编号洞察卡、对比双栏，让长文结构更清晰（见[格式介绍](#格式介绍)）。
- 💾 **独立编辑器**：`--app` 生成单文件编辑器，打开本地 `.md`、草稿自动存浏览器，可部署成在线工具站。
- 🐍 **零依赖**：纯 Python 标准库，无需安装任何第三方包。

**适用场景**：需要把 Markdown / 纯文本排好版、复制到微信公众号后台发表。

**不适用场景**：只想要网页预览、只编辑 Markdown、或发布到知乎 / 小红书 / 掘金等其他平台。

## 快速开始

### 环境

- Python 3（无需任何第三方依赖，标准库即可）

### 基础用法（单篇排版）

```bash
python3 scripts/build_wechat_html.py 文章.md -o 文章.wechat.html
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `-o <路径>` | 指定输出 HTML 路径（默认 `<原名>.wechat.html`） |
| `--title "标题"` | 覆盖首个 H1 检测到的标题 |
| `--theme <配色>` | 默认配色（预览页内仍可切换） |
| `--format <格式>` | 默认结构格式（预览页内仍可切换） |
| `--list-themes` | 列出全部配色与格式并退出 |

生成后用浏览器打开 `.wechat.html`，点「📋 复制正文」，去公众号后台粘贴即可。

### 生成独立编辑器（推荐日常使用）

单篇预览页会把那篇文章写死在页面里；若想要一个**不绑定单篇、可反复用**的编辑器：

```bash
# 生成单文件编辑器（内置示例文档 + 打开本地 .md + 草稿自动保存）
python3 scripts/build_wechat_html.py --app -o app/index.html

# 本地起服务（推荐，剪贴板支持最佳）
python3 scripts/build_wechat_html.py --serve app
# 浏览器打开 http://localhost:8000/index.html
```

`app/index.html` 是一个 755KB 左右的自包含单文件，可直接部署到 CloudStudio / GitHub Pages / Nginx 等任意静态托管，即成为一个在线公众号排版工具。

### 目录结构

```
wechat-formatter/
├── scripts/
│   └── build_wechat_html.py   # 核心脚本：Markdown → 公众号 HTML（纯标准库）

│   └── index.html             # 由 --app 生成的独立编辑器（单文件）
```

## 格式介绍

### 配色 × 结构格式（完全解耦）

工具把「**配色**」和「**结构格式**」拆成两个独立维度：

- **配色（COLOR）**：只决定颜色与字体——强调色、正文 / 标题色、衬线或黑体、引用三色、代码块、表格、分隔线等。
- **结构格式（VARIANT）**：只决定标题 / 引用 / 高亮三要素的**结构形态**——左色条、居中双线、填充色块、虚线标签、填充条、深色块、报刊双线、手账点线、极简细线等。

二者相乘共 **100 种组合**，切换互不干扰。

### 10 套配色（`--theme`）

| id | 名称 | 观感 |
| --- | --- | --- |
| `blue` | 简约蓝（默认） | 通用、科技、资讯 |
| `classic` | 文艺古籍 | 文化、古文、读书、散文（衬线 + 暖金） |
| `tech` | 科技青 | 技术教程、产品 |
| `green` | 清新绿 | 生活、成长、治愈 |
| `warm` | 暖橙生活 | 美食、旅行、亲子（暖橙 + 米色底） |
| `dark` | 暗夜 | 暗色卡片风（深底 + 浅字） |
| `news` | 报刊红 | 资讯、观点、干货长文 |
| `note` | 手账暖 | 随笔、日记、情感（牛皮纸 + 衬线） |
| `minimal` | 极简灰 | 极简、留白、高端调性 |
| `brief` | 商业简报 | 商业、组织、咨询、观点长文（墨蓝 + 编辑感卡片） |

### 10 套结构格式（`--format`）

| id | 名称 | 标题结构 | 引用结构 | 高亮结构 |
| --- | --- | --- | --- | --- |
| `sidebar` | 左色条 | 左侧色条 | 左条色块 | 纯色加粗 |

| `marker` | 虚线签 | 虚线标签 | 胶带条 | 背景标记 |
| `card` | 填充条 | 填充条 | 阴影卡片 | 背景药丸 |
| `night` | 深色块 | 深色块 | 暗色卡片 | 深底药丸 |
| `news` | 报刊双线 | 双线 | 粗左条 | 波浪下划线 |

### 支持的 Markdown 语法

| 语法 | 渲染效果 |
| --- | --- |
| `#`–`######` 标题 | H1 作为标题（不进正文复制区），H2+ 随结构格式变化 |
| `**粗**` `*斜*` `~~删~~` `` `代码` `` | 行内强调 |
| `[文字](链接)` | 带色链接 |
| `![alt](图片)` | 独立成行的图片居中、圆角阴影 |
| `-` / `1.` 列表 | 有序 / 无序列表 |
| `> 引用` | 自动三色分类（见下） |
| ```` ``` ```` 代码块 | 深色背景、等宽、自动换行 |
| `\| a \| b \|` 表格 | 带边框与表头底色 |
| `---` | 居中圆点装饰分隔线 |

### 扩展块语法

在普通 Markdown 之上，工具提供 4 类让长文更立体的块：

**1. 分栏分隔线（文字可自定义）**

```markdown
--- 缘起
```

独立成行写 `--- 任意文字`（或 `*** 任意文字`），渲染为居中「— 任意文字 —」，文字随意改。
旧写法 `SECTION 01` 仍兼容；单独 `---`（无文字）仍是普通圆点分隔线。

**2. 标签卡片**

```markdown
> [!核心判断] 这句话会被做成带小标签的强调卡片
```

引用块首行以 `[!标签]` 开头，渲染为「主题色左条 + 标签 + 内容」的卡片，区别于普通引用。

**3. 编号洞察卡**

```markdown
> [!01] 标题
这里是这一条洞察的描述文字，可以写一两句。
```

引用块首行以 `[!数字]` 开头，渲染为「大号数字 + 标题 + 描述」卡片，适合「01 / 02 / 03」式逐条展开。数字写两位（01、02…）更整齐。

**4. 对比双栏**

```markdown
> [!compare] 过去的做法 | 现在的做法
> 纯文字堆砌 | 结构化卡片
> 复制进后台对不齐 | 内联样式粘贴即所见
```

首行 `[!compare]` 用 `|` 分隔两栏标题；其下**每行** `> 左 | 右` 自动作为一行两列对照（逐行对照，无需 `|||`）。渲染为并排两栏对照卡（左栏主色、右栏绿色），适合「传统 vs 优秀」「旧方案 vs 新方案」。

### 引用自动分色

普通引用 `>` 会根据内容关键词自动判定颜色：

- 🟠 **橙色（编者按）**：命中「编者按 / 按语 / 译注 / 注：/ 按：/ 点评」等
- 🔵 **蓝色（古文）**：命中「曰 / 云：/ 子曰 / 《》/ 诗词 / 论语」等古文体关键词
- 🟢 **绿色（普通）**：默认，无特殊关键词

## 工作原理（简述）

1. **全程内联样式**：每个块级元素用 `<section>` 包裹（比 `<div>` 在公众号后台兼容性更好），样式全部写在标签上；底色挂在内容块外层，避免粘贴丢底色。
2. **Python 兜底 + JS 实时组合**：默认组合由 Python 渲染保证复制内容 100% 正确；预览页把「解析后的块 JSON」和「100 种组合的样式 JSON」嵌入，由页面内 JS 渲染器在切换选择器时实时重渲染，无需预渲染 100 份。
3. **解析器同构**：浏览器端 `parseMarkdown()` 是 Python `split_blocks` 的逐行忠实移植。已用 Node 抽取页面真实 JS 跑同一份源文，与 Python `build_blocks_json` 逐块 JSON 比对，在多篇含表格 / 列表 / 各卡片的文章上均 **100% 一致**——所以编辑器里实时改稿与最终复制结果永远对得上。

## 备注

- 切勿在正文里引入 `<style>`、`<link>` 或 `class`——它们会在粘贴时被公众号后台剥离。
- 复制逻辑优先用 `ClipboardItem('text/html')` 写富文本，失败回退到 `execCommand('copy')` 选中复制，兼顾现代与老旧浏览器。
- 本仓库同时作为 WorkBuddy 技能（`SKILL.md`）提供，可直接被智能体调用完成排版任务。
